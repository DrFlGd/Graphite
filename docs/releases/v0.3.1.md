A polish release after a review of the whole interface: no new milestone, but a long list of things that looked or behaved wrong now don't.

## Fixed

- **Opening a note no longer changes it.** Before, simply opening a note could save it again with small formatting changes, and `![[file]]` embeds were rewritten as `\![[file]]`. Files are now left byte for byte as they were until you type, embeds keep their `!`, and clicking an embed such as `![[mount.stl]]` opens the file.
- **Project hubs and saved queries** no longer act on the note you had open before. The command palette and side panel used to offer "Delete" or "Promote" for that note.
- **Linux:** thumbnails and PDF pages load. The app also no longer reloads notes and previews many times a second: it had been treating simply reading a file as an edit.
- **Sidebar:** the filter box is one line, the navigation buttons fit, notes are sorted by name, and folder headings read "Daily" rather than "NOTES/DAILY".
- **Dark mode:** checkboxes, selects, date fields and scrollbars follow the theme.
- **Side panel:** long property names and values truncate with a tooltip. Created, updated and id move to a small footer. Each linking note is listed once, and links to files say "file" instead of "create".
- **Editor:** the toolbar stays on one row in narrow panes, tasks are single-spaced, a first `# heading` that repeats the title is hidden (it stays in the file), and inline fields such as `due:: 2026-10-16` show as small chips.
- **Sync settings** take keyboard focus and close with Escape.
- **Search** previews show plain text instead of Markdown. Notes titled with a date no longer list every capture from that day as an unlinked mention.

## Improved

- **Tasks and saved queries** lead with their filters, and the raw query sits behind "Edit query". Links in task text are links. Boards say "No project" with each checkbox beside its text. Tables show dates as YYYY-MM-DD and the project a task inherits from its note.
- **Project hubs** open with the project note's own text and photos, collapsible. They list sources and decisions that name the project only in their front-matter (`project: "[[Garden Robot]]"`); such links now count everywhere, as typed links named after the property.
- **Graph:** stays in view while it settles, keeps unlinked notes near the middle, and its legend covers every note type shown. The side-panel graph is centred.
- **Layout:** the sidebar and the side panel can be hidden from the tab bar or the command palette, and long titles wrap.
- **Phone:** inbox cards stack their controls under the text, Tasks start with the task list behind one filter button, hubs scroll as one page, and read mode has no editor toolbar and larger checkboxes.

The search index rebuilds itself once after updating, which takes a moment on a large vault.

## Install

Pick the file for your platform below. The builds are not code-signed yet, so the first launch needs one extra step:

- **Windows** (`Graphite_0.3.1_x64-setup.exe` or the `.msi`): in the SmartScreen prompt choose "More info", then "Run anyway".
- **Linux**: `.AppImage` (make it executable), `.deb` or `.rpm`.
- **Android** (`graphite-v0.3.1-android-arm64.apk`): open it on the phone and allow installing from that app. Each release is signed with a fresh key, so uninstall the previous version before installing a new one.
- **Relay** (`graphite-relay-v0.3.1-linux-x86_64.tar.gz`): run it on a machine both devices can reach, ideally behind HTTPS.

There is no macOS build in this release. The `graphite-cli-*` archives contain the command-line tool.

## Known limits

As in 0.3.0: video quality choice, chapters and PDF metadata lookup, DXF/AI and STEP conversion, duplicate-file warnings and the website mirror importer are not in yet. On the phone there is no voice capture, home-screen widget or reminders, and the Android app pairs by pasted invite rather than QR code. The phone layout was checked at phone width on a desktop; touch handling on a real device has not been reviewed.
